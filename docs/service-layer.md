# IM 服务层更新（2026-10-29）

个人记忆入口不在本次范围。

## 职责

IM 保存渠道身份、用户订阅引用、接收/交付记录、通知偏好和任务视图。meta-agent 保存执行权威状态、执行权限、人工工单及定时执行状态。RuntimeAdapter 是调用入口。

### 定时执行

普通提醒仍由 IM 投递；kind=talk 的定时执行由 runtime 公开 ChannelScheduleClient 接管，独立进程运行，停止 IM 不停止已注册的执行。IM 重新启动后读取持久结果补发。只有后端接管后才报告接管成功。

旧的 kind=talk 订阅在启动后自动交接。新订阅固定时区，不随服务器时区变化漂移；/notify timezone Asia/Shanghai 设置后续聊天及新增定时请求的时区，已有订阅保持原值。

每次执行采用独立工作目录；单个调度服务串行运行。运行预算、轮数和超时沿用配置；未配置时预算与轮数采用 runtime 默认值，调度执行超时默认 30 分钟。重复请求幂等。错过超过一小时的周期触发跳过；已认领但没有可靠结果的执行标记 unknown 并暂停，不自动重跑。取消订阅停止后续触发，不中断已开始的执行。

部署必须同时更新并构建 runtime 的库及 CLI。旧 runtime 缺少公开定时服务时，IM 保留待交接状态并提示，不退回 IM 自行执行。

### 待处理交互

随时可发送 /pending 查看人工请求、本地待决策和待确认的任务提议；/respond H1 填写 选择工单，随后 /respond 内容，/respond 提交 正式回填。复用 runtime 的字段验证、身份绑定、终态检查和幂等回执；人工作业、澄清及运行时创建的审批请求共享渠道入口。批准权限与执行恢复仍由 runtime 决定，IM 不新增自动批准规则。

Auto 决定回复绑定 wakeId；引用旧问题、重复回答、后端已变化的请求不作为当前决定执行。普通聊天中的“同意”不会自动变成工具授权。现有 runtime 尚未支持的交互不会被 IM 模拟为已授权。

### 成果交付

runtime CLI 最终 result 携带已注册 artifacts；IM 忽略工具调用意图中的路径，也不再自动扫描整个工作目录。聊天仍支持显式 outbox/ 交付约定。文件必须在工作区内部，交付前快照并保存 SHA-256，发送时验证快照未变化。/tasks 模式中 resend A1 可重发保留期内的成果快照。

### 通知

/notify 查看；mute / unmute 静音与恢复；quiet 22:00-08:00 Asia/Shanghai 设置免打扰；quiet off 关闭；timezone Asia/Shanghai 设置个人服务时区；changes on/off 控制定时摘要是否只在内容变化时发送。均加 /notify 前缀。

静音和免打扰延迟主动通知，保留待发记录；直接命令回复正常发送。恢复后补发；相同定时成功结果可去重，失败不会因内容相同被忽略。运行时任务从其他状态变为 finished/failed 时产生状态通知。未实现跨渠道账号自动迁移或外部业务连接器。

## 验证范围

自动测试覆盖幂等、取消、周期首个截止时间持久化、进程中断不重放、时区与夏令时、IM 回执去重、免打扰、显式产物交付及任务续聊。未使用真实微信账号或付费模型执行端到端任务；源码与构建验证不等于已部署重启在线服务。
