# 常驻助理（1.5）

## 目标

- 不再手动进入/退出模式：所有消息交给一个常驻的 simple_auto 助理。
- 聊天、搜索、提醒等直接处理；大任务和用户一起确认工作文件夹，再启动 auto 工作任务（独立进程）。
- 主动发出的消息（结果、状态、待决策、提醒、定时结果）能对应回原来的任务或提醒。
- 聊天不再每条消息冷启动，也不被长时间的工作任务挡住。

## 组成

| 模块 | 职责 |
|---|---|
| `src/message-trigger.mjs` | 快捷命令解析（`/auto`、`/tasks`、`/pending`、`/respond`、`/new`、`/notify`）；其他一律交给助理；旧模式标记只回提示 |
| `src/personal-agent.mjs` `route()` | 按上下文决定去向：填写中的工单 → 工单；`决定 A1 …` 或引用【待决策】→ 任务；对【P·确认】的“确认/取消/编号” → 提议；其他 → 助理（附引用对象、通知、待处理事项） |
| `src/talk-host.mjs` | `meta-agent serve` 的客户端与监管：启动、`ready` 握手、轮次、工具转接、ping 健康检查、崩溃重启、反复崩溃后停用 |
| `src/assistant-tools.mjs` | 助理可调用的 IM 工具声明与实现 |
| `src/workspaces.mjs` | `IM_WORKSPACE_ROOTS` 白名单、真实路径校验、文件夹列表/详情/清单搜索、新建规划 |

## 一条聊天消息

1. 收件落盘（与 1.4 相同的去重和持久化）。
2. 路由为 `talk`：拼上 `[期间发给用户的通知]`、`[用户引用的任务/提醒/提议]`、`[用户引用的消息]`、`[待处理]`，以及附件。
3. 调度：聊天有独立额度（不占 `META_AGENT_MAX_CONCURRENT`），同一用户的聊天串行。
4. 常驻助理可用时，在 IM 进程内把这一轮发给 `serve`（`transport: 'serve'`），显示“正在输入”，超过 `IM_SLOW_NOTICE_MS` 再回“正在处理”。不可用时用原来的单次 CLI worker。
5. 轮次结束：回复正文，加上本轮工具产生的确认行（如“⏰ 已创建 R1 …”），发送工作区 `outbox/` 和已登记的文件，记录耗时（排队、首个事件、总计）。

`serve` 进程里的会话写入 `personal-agent/runtime-sessions/`，与单次运行共用，切换两种方式不丢历史。

## 工具（IM 执行，IM 校验）

| 工具 | 说明 |
|---|---|
| `workspace_search` / `workspace_list` / `workspace_peek` | 只读元数据：名称、README/package 摘要、git 分支/远程（去凭据）/未提交改动/最近提交、两层目录。路径必须解析到白名单根目录内部 |
| `task_propose` | 生成【P·确认】卡片（IM 写的固定格式），取代该用户未确认的旧提议；24 小时过期 |
| `task_status` / `task_steer` / `task_decide` / `task_cancel` | 只能操作本人的任务；补充、决定、取消由 IM 回显实际交出的内容 |
| `reminder_create` / `reminder_list` / `reminder_cancel` | 按用户时区解析时间，复用机器人的提醒校验与上限 |
| `human_open` | 发送工单列表，或进入某张工单的逐项填写 |
| `ops_query` | 交给 runtime 任务运维控制台 |

## 确认由 IM 判断

auto 以 `--yes` 运行，默认预算很高，所以开工必须是用户的明确回复，而不是模型的判断：

- 只有对待确认提议的“确认/好/开始…”“取消/算了…”“2”等短回复会被直接处理；每个用户同时最多一个待确认提议。
- 引用【P·确认】回复同样处理；提议已确认、取消、被取代或过期时如实回复，不会开工。
- 其他回复（如“目录换成 xxx”）交给助理，助理重新提议。
- 确认时重新校验路径；需要新建的文件夹此时才创建。

## 主动消息

IM 发出的消息带标记：`【A1·结果】`、`【A1·状态】`、`【A1·已开始】`、`【A1·补充】`、`【待决策 A1】`、`【R1·提醒】`、`【R1·定时】`、`【P1·确认】`；发件记录同时保存 `ref`。

- 引用回复：先找标记，找不到时用引用正文匹配最近带 `ref` 的发件记录。
- 结果、状态、待决策、提醒、定时结果记为“通知”，下一轮聊天开头附给助理一次（游标前进）。
- 静音、免打扰、重试与 1.4 相同。

## 故障与恢复

- `serve` 退出：进行中的轮次以 `serve_crashed` 结束并回复；下一条消息时重启。10 分钟内异常退出超过 5 次则停用，改用单次运行。
- `serve` 无响应：超过 ping 间隔 + 超时未收到 pong，杀掉重启。
- 一轮还没开始 `serve` 就不可用：这一轮改走单次运行（`forceCli`）。
- 机器人重启时正在进行的 `serve` 轮次：标记 `interrupted` 并提示重发，**不重放**（它可能已经调用过工具）。工作任务（auto）仍是独立进程，不受影响。

## 存储、查询与清理

| 方面 | 做法 |
|---|---|
| 写盘 | `DurableStore`：内存状态 + 快照 `state.json` + 追加日志 `state.journal`。`update()` 通过代理记录改动到的记录（集合 + 键），提交时只追加这些记录的一行 JSON 并 fsync；抛错时用撤销日志回滚内存。日志超过 max(2MB, 快照/2) 或 5000 行、每日清理后、退出时合并为新快照。`IM_STORE_VERIFY=1`（测试默认开启）会核对是否有绕过 `update()` 的写入。 |
| 合并提交 | 每轮 tick 的定时提醒、路由和派发包在一个 `batch()` 里，一次提交后才启动进程或常驻轮次（先落盘再产生副作用）。发送成功/失败标记延迟提交（≤2 秒，与下一次提交合并）。一条聊天消息：收件 1 次、路由+派发 1 次、结果+回复 1 次，发送标记合并进后续提交；没有整份重写。 |
| 查询 | `StateIndex` 在启动时建立、随每次提交更新：待处理收件、排队/运行中执行、结果未知的执行（用于隔离工作区）、待发送消息、每个用户带标记的最近 300 条发件（引用匹配）。每秒的循环只遍历这些集合，不再扫描保留期内的全部记录。 |
| 任务核对 | `syncTasks()`：只看还可能变化的任务（IM 侧排队/运行中、待决策、runtime 状态非终态，或 3 天内有活动），对它们的工作区做一次进程内 `TaskControlService.tasks()` 查询（结果里带待决策问题，不再逐个 inspect）。状态变化或新的待决策才写盘；核对时间和错误只在内存（`/tasks inspect` 显示“本次启动后尚未核验”或最近错误）。连续 3 次查不到记为 `untracked` 并退出核对。有进行中的任务时间隔 `META_AGENT_DECISION_POLL_MS`，否则 10 分钟；没有可核对的任务时不加载 runtime 模块。 |
| 定时同步 | 只同步生效中的定时和已取消但还没确认停下的定时；`submit` 首次和每 10 分钟重申一次；每次只读调度器的小状态文件，状态变了才读回执（按时间水位跳过已处理的，只保留最近 20 个回执编号）；`nextAt`/`blocked` 变了才写盘；取消在确认没有运行中的执行后标记 `runtimeCancelled`，此后不再参与同步。只有存在生效中的定时、且调度进程不在运行时才拉起它（最多每分钟检查一次）。 |
| 瘦身 | 收件只保存路由、回复地址和附件事实（`freshMedia`），不存原始报文和每条消息的 context token；已完成执行删除 runtime 配置、提醒列表、图片路径副本，提示词 ≤120 字、回复 ≤100 字（任务执行 ≤500 字，任务记录上的结果 ≤4000 字）；已送达消息不再保存正文（带标记的保留前 600 字供引用匹配）、文件路径和回执。旧记录在升级后首次启动时瘦身一次（`storeVersion: 2`）。 |
| 清理 | 默认 7 天，见 README“数据保留”。独立目录任务的工作区只有 `IM_PRUNE_TASK_WORKSPACES=true` 时删除，且只删 `personal-agent/workspaces/` 下、任务已结束、无运行中/未知执行、无待决策、runtime 已终态的；任务记录保留并标记 `workspaceRemoved`，不能再继续。 |

## 验证

- `test/durable-store.test.mjs`：只追加改动的记录、崩溃后回放、抛错回滚、批量与延迟提交、监听、末行撕裂与中间损坏、合并阈值、绕过写入检测。`test/storage.test.mjs`：每条聊天消息的提交次数、记录瘦身、旧记录升级瘦身、聊天文件/定时运行目录清理和独立工作区开关。
- `test/assistant.test.mjs`：常驻轮次、续接会话、交付文件、正在输入；`/auto` 交给助理；提议确认/改选/新建/取消/取代/过期；工具路径白名单与符号链接；引用与通知；任务工具的归属与回显；时区提醒；中断与退回；`TalkHost` 对接脚本化 `serve` 进程（工具往返、崩溃重启、停用、版本探测）；文件夹清单与时区解析。
- 端到端（开发时手动）：IM 的 `TalkHost` 驱动真实 `meta-agent serve`（runtime 源码）+ 脚本化模型，完成“搜索文件夹 → 提议 → 用户确认 → 在该文件夹启动任务”。未使用真实微信或付费模型。
